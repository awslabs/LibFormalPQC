# SLH-DSA Reference Code in SPARK/Ada

This library implements SLH-DSA, the Stateless Hash-Based Digital Signature
Algorithm (formerly known as SPHINCS+), as specified in
[FIPS 205](https://doi.org/10.6028/NIST.FIPS.205), for the
SLH-DSA-SHAKE-256s parameter set only.

This implementation is written in SPARK - a subset of Ada that is designed
for static verification - and has been subject to verification
with the SPARK toolset.

If the reader is not familiar with SPARK, then [start here](https://learn.adacore.com/).

## IMPORTANT WARNING

This implementation is absolutely NOT intended for production or any use
in a "high assurance" setting. In particular:

* ONE function (SLH.Hash.PRF_Msg) was implemented by human hands. *Everything* else,
including all test scripts, contracts and proofs, were generated from the FIPS-205 document
by Claude Opus 5.5 in a single kiro-cli session.

* Constant-time behaviour is not verified, at the level of either the source
code or the generated code.

* Secret and intermediate values are not sanitized at present.

* Performance is unlikely to be competitive with other, more optimized,
implementations.

## Structure

The code follows FIPS 205 section by section. Names of subprograms and
variables follow the specification as closely as possible.

The visible part of package `SLH` (in `src/slh.ads`) is the application
interface from FIPS 205 section 10:

| FIPS 205 | SPARK |
|----------|-------|
| Algorithm 21, `slh_keygen` | `SLH_Keygen` |
| Algorithm 22, `slh_sign` | `SLH_Sign`, `SLH_Sign_Deterministic` |
| Algorithm 23, `hash_slh_sign` | `Hash_SLH_Sign`, `Hash_SLH_Sign_Deterministic` |
| Algorithm 24, `slh_verify` | `SLH_Verify` |
| Algorithm 25, `hash_slh_verify` | `Hash_SLH_Verify` |

Keys and signatures are byte arrays in the formats of FIPS 205 Figures 15,
16 and 17. Where FIPS 205 generates random values (SK.seed, SK.prf, PK.seed
and addrnd), the caller supplies them as parameters, and they shall be
generated by an approved random bit generator. The pre-hash functions
provided are SHA3-512 and SHAKE256, which are the ones from FIPS 202 with
the security strength that FIPS 205 section 10.2 requires for this
parameter set.

Everything else is declared in the private part of package `SLH`:

| FIPS 205 | SPARK |
|----------|-------|
| Section 4.1, hash functions | package `Hash` |
| Sections 4.2 and 4.3, addresses | package `ADRS` |
| Section 4.4, `toInt`, `toByte` and `base_2b` | package `Conversions` |
| Section 5, WOTS+ | package `WOTS` |
| Section 6, XMSS | package `XMSS` |
| Section 7, the hypertree | package `HT` |
| Section 8, FORS | package `FORS` |
| Figures 11, 13, 14 and 17, signature formats | package `Formats` |
| Section 9, internal functions | `SLH_Keygen_Internal`, `SLH_Sign_Internal`, `SLH_Sign_Internal_Deterministic`, `SLH_Verify_Internal` |

All the internal subprograms are pure functions. In particular, an address
(ADRS) is an `in` parameter, and each address used is a new value built
from it, where FIPS 205 updates ADRS in place.

The child package `SLH.KAT` (in `src/slh-kat.ads` and `src/slh-kat.adb`)
can see the private part of `SLH`, and runs the tests described below.
It is not part of the library proper, and is excluded from the `zfp`
(bare metal) build.

The only dependency is [LibKeccak](https://github.com/damaki/libkeccak),
a SPARK implementation of SHA3 and SHAKE from Daniel King, which is a
sub-module of this repository.

## Verification

### Proofs

The SPARK toolset proves, automatically:

* Absence of run-time errors (no overflow, range or index errors) and
of undefined behaviour, and data-flow correctness.

* That each subprogram meets its contract. Most internal subprograms have
functional postconditions stated in terms of the FIPS 205 pseudo-code.

* Round-trip theorems for each layer of the scheme, as ghost procedures
named `Theorem_Round_Trip`:
  * WOTS+: the public key computed from a signature of M is the public key.
  * XMSS: the root computed from a signature of M is the root of the tree.
  * Hypertree: a signature of M verifies against the root of the top tree.
  * FORS: the public key computed from a signature of md is the FORS
    public key, for any md.

* Correctness of SLH-DSA: a signature made with a key from key generation
verifies with the matching public key, for any message, context string and
addrnd. This is `Theorem_Correctness` for the internal functions, and
`Theorem_Correctness_Pure` and `Theorem_Correctness_Pre_Hash` for the
application interface.

The theorems are about the structure of the algorithms. They treat the
hash functions as uninterpreted functions, so they say nothing about
security, and they don't show that the hash functions are SHAKE256.
The tests below check that.

Mutation testing (introducing deliberate errors) was used to check that
the contracts and theorems are strong enough to detect errors.

### Tests

The tests in `tests` check the code against:

* Python reference models of FIPS 205 sections 4 to 9, in
`SLH/checkers/check_*_kats.py`, which are shared by all the
implementations of SLH-DSA in this repository. Each model follows the FIPS 205 pseudo-code
closely, including its in-place updates of ADRS, so it is independent
of the SPARK code. The section 4.1 checker uses Python's `hashlib`.

* The NIST ACVP test vectors for SLH-DSA-SHAKE-256s, in `../acvp`,
covering key generation, signing and verification, through both the
internal interface (section 9) and the application interface (section 10),
with pure and pre-hash signing, and contexts of up to 255 bytes. The
signature verification tests include modified and wrongly-sized
signatures and modified messages.

## Getting the tools

This library was developed on an Apple Silicon Mac running macOS.

You need:

1. GNAT (the GCC Ada compiler) and the `gprbuild` build tool. The code was
developed with GNAT FSF 16.1.0 and GPRBUILD 26.0.0.

2. The SPARK toolset (`gnatprove`), to reproduce the proofs. The code was
developed with gnatprove FSF 16.1.0, with the Z3, CVC5 and Alt-Ergo provers
that ship with it.

3. Alire (`alr`), to configure LibKeccak.

4. Python 3, to check the test results. Only the standard library is
used. The code was developed with Python 3.13.

5. GNU make.

The [Alire](https://alire.ada.dev/) package manager can install all of
the Ada tools. For example:

```
alr toolchain --select     # pick gnat_native and gprbuild
alr get gnatprove
```

then add the `bin` directories of GNAT, gprbuild and gnatprove to your
`PATH`. See the README for ML-KEM in `../../MLKEM/spark_ada` for more
detail.

Check that the tools are on your `PATH` with

```
gprbuild --version
gnatprove --version
python3 --version
```

## Cloning and configuring LibKeccak

```
git clone https://github.com/awslabs/LibFormalPQC.git
cd LibFormalPQC
git submodule init
git submodule update
cd libkeccak
alr build
cd ..
```

`alr build` generates the configuration files (in `libkeccak/config`)
that `libkeccak.gpr` needs.

## Building the library

```
cd SLH/spark_ada
gprbuild -P slh.gpr
```

should result in `lib/libslh.a`.

By default, `slh.gpr` enables all compiler warnings and treats them as
errors. To build without them, add `-XSLH_COMPILE_CHECKS=disabled`. Other
options are set with the `SLH_BUILD_MODE`, `SLH_RUNTIME_CHECKS`,
`SLH_CONTRACTS` and `SLH_RUNTIME_MODE` scenario variables; see `slh.gpr`.

## Running the tests

```
cd SLH/spark_ada/tests
make
```

This builds the library and the test program `tkats`, runs each group of
tests, and checks the results. It takes about a minute, and should end with:

```
All hash function KATs passed
...
All WOTS+ KATs passed
...
All XMSS KATs passed
...
All hypertree KATs passed
...
All FORS KATs passed
...
All SLH-DSA KATs passed
--- Checking NIST ACVP tests ---
python3 ../../checkers/check_acvp.py check acvp_results.txt
ACVP KeyGen         10 passed
ACVP SigGen         14 passed
ACVP SigGenPure     14 passed
ACVP SigGenPreHash   4 passed
ACVP SigVer         14 passed
ACVP SigVerPure     14 passed
ACVP SigVerPreHash   3 passed
All ACVP tests passed
```

`make` stops at the first group that fails, and each checker prints a line
starting `FAIL` for each test that fails.

Each group can also be run on its own:

| Target | Tests | Checked by (in `SLH/checkers`) |
|--------|-------|------------|
| `make check_hash` | Section 4.1 hash functions | `check_hash_kats.py` |
| `make check_wots` | Section 5, WOTS+ | `check_wots_kats.py` |
| `make check_xmss` | Section 6, XMSS | `check_xmss_kats.py` |
| `make check_ht` | Section 7, the hypertree | `check_ht_kats.py` |
| `make check_fors` | Section 8, FORS | `check_fors_kats.py` |
| `make check_slh` | Section 9, internal functions | `check_slh_kats.py` |
| `make check_acvp` | NIST ACVP vectors, sections 9 and 10 | `check_acvp.py` |

`make clean` removes the test and benchmark programs, all results, and
the objects of the library and LibKeccak.

By default, the tests build the library without run-time checks of
contracts and assertions, but with all other run-time checks (overflow,
range and index checks). Some postconditions recompute whole trees, so
checking them at run time is very slow. To check them anyway, run

```
make clean
make CONTRACTS=enabled
```

which takes much longer: the XMSS tests alone take about six minutes.
The Makefile rebuilds the library whenever its compiler switches change,
so `make` on its own goes back to the default.

The `tkats` program can also be run directly, as `tkats hash`, `tkats wots`,
`tkats xmss`, `tkats ht`, `tkats fors` or `tkats slh`, which write test
inputs and results to standard output, or as `tkats acvp`, which reads
ACVP test cases from standard input.

### The ACVP test vectors

The files in `SLH/acvp` come from the NIST
[ACVP server repository](https://github.com/usnistgov/ACVP-Server), in
`gen-val/json-files/SLH-DSA-keyGen-FIPS205`, `SLH-DSA-sigGen-FIPS205` and
`SLH-DSA-sigVer-FIPS205`, file `internalProjection.json`. Each file is
filtered to the SLH-DSA-SHAKE-256s parameter set, and its pre-hash tests
are filtered to SHA3-512 and SHAKE-256. The directory is shared by all
the implementations of SLH-DSA in this repository. `check_acvp.py input` converts
them to the input format of `tkats acvp`, and `check_acvp.py check`
checks the results.

### macOS

If linking fails because the linker can't find system libraries, point it
at the Command Line Tools SDK:

```
export SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk
```

Warnings from `ld` that object files were "built for newer 'macOS' version"
are harmless.

## Running the benchmarks

```
cd SLH/spark_ada/tests
make bench
```

builds the benchmark program `tbench` (in `tests/tbench.adb`) once for
each build variant of the library, runs each one, and prints a summary of
the median CPU cycles for `SLH_Keygen`, `SLH_Sign` and `SLH_Verify`. The
summary is also written to `tests/bench/summary.txt`, and the results of
each variant to `tests/bench/VARIANT.txt`.

The variants are every combination of these `slh.gpr` scenario variables:

| Variable | Values (Makefile variable to change them) |
|----------|--------|
| `SLH_BUILD_MODE` | `debug`, `Og`, `O1`, `O2`, `O3`, `Os` (`BENCH_MODES`) |
| `SLH_RUNTIME_CHECKS` | `enabled`, `disabled` (`BENCH_RUNTIME_CHECKS`) |
| `SLH_CONTRACTS` | `disabled` (`BENCH_CONTRACTS`) |

The `profile` build mode is left out, since it is `O2` with debug
information. Contract checks are left out by default, because the
postconditions recompute whole trees: at `O2`, one `SLH_Keygen` takes
about 90 seconds with them, and one `SLH_Sign` more than 7 minutes. To
include them anyway, use
`make bench BENCH_CONTRACTS="enabled disabled" BENCH_ITER="1 1 1"`. LibKeccak is always built optimized and without run-time
checks, so only the SLH code differs between variants.

Each operation is run once to warm up, then timed 10 times for keygen and
sign and 50 times for verify. Set `BENCH_ITER` to change these, for
example `make bench BENCH_ITER="3 3 20"`. Every signature is checked with
`SLH_Verify` outside the timed region. For example, to benchmark only the
optimized builds without contract checks:

```
make bench BENCH_MODES="O2 O3" BENCH_CONTRACTS=disabled
```

The cycle counter is the one from mlkem-native, in `SLH/hal` (see
`SLH/hal/README.md`). On macOS it uses Apple's private `kperf` framework,
which only works as root, so `make bench` runs each benchmark with
`sudo`, which may ask for your password. On Linux it uses
`perf_event_open` and needs no `sudo`, but
`/proc/sys/kernel/perf_event_paranoid` must be 2 or less. If the counter
doesn't work, `tbench` stops with an error message instead of reporting
results.

## Reproducing the proofs

From `SLH/spark_ada`:

```
gnatprove -P slh.gpr -u slh.adb -j0 --prover=z3,cvc5,altergo -f --output=oneline
```

This takes about a minute on an Apple M-series Mac, and should end with

```
Success: all checks proved (... checks).
```

with no "medium", "high" or "warning" messages before it. The number of
checks also includes checks of LibKeccak from earlier runs.

The options:

* `-u slh.adb` proves the `SLH` package only. Without it, gnatprove also
re-proves all of LibKeccak, which takes several minutes more.

* `--prover=z3,cvc5,altergo` is needed because `libkeccak.gpr` asks
for the CVC4 prover, which no longer ships with gnatprove.

* `-f` forces all proofs to be redone. Without it, gnatprove re-uses
results from earlier runs where it can, which is faster, but after
changes to the code it can report spurious "step limit" failures.

* `-j0` uses all CPU cores.

The proof options (proof level, step limit and timeout) are set in the
`Prove` package of `slh.gpr`.

To prove one subprogram, use `--limit-subp=slh.ads:LINE`, where `LINE`
is the line of its declaration in `src/slh.ads`.

## Known compiler issues

GNAT FSF 16.1.0 crashes ("GNAT BUG DETECTED") on some expression
functions that gnatprove accepts. The code avoids these by using normal
functions with postconditions instead, and comments in `src/slh.ads`
mark each place (`XMSS.Concat`, `HT.Layer_PK`, and `Formats.Get_R`,
`Get_SIG_FORS` and `Get_SIG_HT`). If you change the code, build it as well
as proving it.
